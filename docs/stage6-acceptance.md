### 2.2. Критические ошибки безопасности и потери данных — НЕ НАЙДЕНЫ

- **SQL-инъекции:** все запросы к БД — параметризованные `prepare`/`run` (`lib/db.ts:96-112`); DDL-скрипты статичны.
- **Клиентские данные:** атрибуция проходится через whitelist-фильтры (`lib/attribution.ts`): utm-ключи/алиасы, значения по regex с лимитом 200, click ID из фиксированного списка, referrer только http(s), страницы/время по строгим форматам; всё остальное отбрасывается. Инъекционные значения (в т.ч. `utm_source_injection: "google; DROP TABLE orders;--"`) не сохраняются — покрыто тестами.
- **Утечки:** в ответах только `{ok, id}` / `{ok:false, error, field}`; стек и внутренние ошибки не отдаются (500 — обобщённое сообщение, детали только в `console.error`).
- **Потеря данных:** в `lib/`, `app/`, `components/`, `data/` нет `DELETE`/`DROP`/`UPDATE`, `fs.rm`/перезаписи файлов; в тестах `fs.rmSync` — только по временным каталогам `%TEMP%`, созданным самим тестом (в `finally`). Миграция БД — только `ALTER TABLE ADD COLUMN`, существующие строки не затрагиваются (покрыто тестом `db-migration`).
- **Безопасность настроек:** `next.config.ts` — только `reactStrictMode: true`; публичных секретов в коде нет.
